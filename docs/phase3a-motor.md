# Phase 3A motor training

## Continuing a population

Use **Continue a previous population** on the Phase 3A page to start a new run from a selected terminal M0-M7 run. The checkpoint restores every genome and its partial fitness, evaluated trial rounds, species lineages, innovation and split-node maps, champion, history, episode number, and NEAT random state. Enter additional trial episodes; training continues at the next episode, including an unfinished evolution. The source run remains intact.

Continuation requires the same session, agent count, seed, backend, world generation, arena, inputs, and training settings. A service restart marks the old run interrupted; it does not silently relaunch Minecraft agents. Checkpoints written before the full-state format can restore their whole population and species history, but they restart the current evolution at its first trial, resetting partial fitness. Their missing random and split-node state is reconstructed where possible, so the continuation is a new deterministic branch rather than an exact replay.

The Phase 3A performance view follows the `motorResume` chain when a continuation is selected. It loads saved reward and throughput samples, trial outcomes, generation fitness, and species reports from every linked run, then adds live samples from the current run. Continuation markers separate runs in the charts; each run keeps its own artifacts and downloadable evolution history.

## Full Run curriculum

**Full Run** configures M0 through M8 as one saved sequence. Each session has its own agent count, trial episodes, steps per episode, step interval, terrain seed, and client backend. Optional minimum success rate and best fitness conditions gate M0-M7; when a gate is missed, the configured number of attempts continues the full population from that stage's checkpoint. M8 evaluates the frozen M7 champion once on a different seed and can have a success-rate condition. M0-M7 must each contain at least one complete NEAT evolution so a trained champion is available for the next session.

The control service stores the plan and starts the next session only after the previous run completes and its conditions pass. Closing the dashboard does not stop the sequence. After a control-service restart, an interrupted session resumes from its last checkpoint when possible. **Pause after current session** prevents the next session from starting; **Stop Full Run** cancels the active run and sequence. Each stage's run IDs, results, status, and error remain visible in the Full Run section.

Training → Phase 3A provides nine individual sessions, M0–M8. Each session starts a Minecraft run with a NEAT population. The agent receives 27 movement, target, physics, and depth inputs; its nine outputs control movement, jump, sprint, sneak, and look direction. Flat sessions M0–M2 do not require jumping, so their fitness can select against it; obstacle sessions need fresh exploration when the previous champion is transferred. Older 12- and 13-input checkpoints migrate their existing weights and full population without changing their learned behavior.

| Session | Arena task                                          |
| ------- | --------------------------------------------------- |
| M0      | Straight flat lane                                  |
| M1      | Seeded target directions across trial rounds        |
| M2      | Long flat lane for sprinting                        |
| M3      | One-block barrier                                   |
| M4      | Seeded obstacle course                              |
| M5      | Uneven block heights                                |

Clicking **Run** selects or creates the dedicated superflat world if no other Minecraft run is active. The control service saves the existing world and starts the motor world. Each agent occupies its own barrier-bounded arena cell, with a gap between cells. Player combat and mob spawning are disabled. Arena blocks are prepared once; agents return to spawn and release movement controls before each trial episode. The world selected before motor training remains stored and can be reactivated from Training worlds; the service does not delete it.

The NEAT population has at least eight genomes. Every genome is evaluated in three shared trial rounds before an evolutionary generation completes. When agents are fewer than genomes, multiple trial episodes are needed per round; the dashboard shows trial episodes and completed NEAT evolutions separately. M1 uses one seeded target direction per round; the other sessions use three seeded target distances. Every genome in a round gets the same relative target, and the three scenarios stay fixed across evolutions so fitness remains comparable. Fitness averages the three trial rewards, which reflect target progress, a one-time arrival bonus, step cost, and death. A trial stops controlling an agent as soon as it reaches the target. Per-trial reports include success rate and mean steps to target.

NEAT mutates weights, connections, and nodes, tracks innovation numbers, and crosses parents within compatible species. New genomes begin with sparse input-to-output connections and all bias-to-output connections. Species persist across evolutions; offspring are allocated by shared fitness, stagnant species stop reproducing, and the global champion survives. New training populations adapt their compatibility threshold toward roughly three to six species, reserve offspring for up to four strong species, and replace about 10% of each new generation with fresh explorer genomes. When a new session inherits a champion, a quarter of its initial population is seeded with fresh genomes so skills such as jumping can appear even when the previous champion never used them. Existing full-state checkpoint continuations retain their saved evolution version and random state; a new stage sourced from a champion uses the updated rules. The checkpoint includes the population, champion, species lineages, compatibility threshold, and the most recent 256 evolution reports. Complete fitness/species history is saved in `evolution.jsonl`; compact trial outcomes are saved in `motor-trials.jsonl`. The run atomically updates `checkpoint.json` after every completed episode. M1–M7 load the latest completed previous-session champion when available. M8 requires an evolved M7 checkpoint and a different terrain seed, then evaluates unchanged champion copies without reproduction or weight updates.

Motor runs collect pose, local physics, and an 8×6 local geometry image with a 16-block range on protocol agents; this keeps input sampling bounded with larger populations. The policy has 27 inputs: world and agent-relative target direction, target distance, world and agent-relative velocity, yaw and pitch, ground and jump state, water and collision state, and selected lower, middle, and upper depth rays with a validity signal. Its nine outputs control forward, back, left, right, jump, sprint, sneak, yaw change, and pitch change. Fabric agents offer an RGB camera but use renderer capacity and currently have no local depth channel. The NEAT policy consumes available geometry when provided. Checkpoints from the prior 12- and 13-input layouts migrate their full populations and saved innovation state when loaded. M7 and M8 use generated arena terrain in a superflat world, rather than a naturally generated overworld. Terrain and target layouts are deterministic for the session seed so runs can be compared. Downstream code can load a frozen checkpoint through `loadMotorSkill(sourceRunId, artifactRoot, session)`, call `reset`, then provide a policy observation with a motor target delta to `act`.
